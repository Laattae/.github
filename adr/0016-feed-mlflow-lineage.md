# 0016. 피드 생성 시도를 MLflow 실행과 연결한다

- 상태: 제안
- 날짜: 2026-11-25
- 범위: lattae-feed

## 맥락
새 사진 워커는 PostgreSQL에 버전과 해시를 저장하지만 기존 수동 MLflow 가져오기 경로와 연결되지 않는다. 사용자가 DB 영상의 버전 확인과 MLOps 통합 완료를 요청했다. 승인 ADR 0007의 멱등 저장과 0011의 설정·키 분리, 제안 ADR 0015의 추적 원칙을 유지한다.

## 결정
- 생성 시도별 고유 실행 ID를 MLflow run과 1:1 연결한다. DB의 시도 기록과 최종 article.generation_config.feed_generation에 mlflow_run_id, experiment_id, 추적 상태를 저장한다. 샘플 생성과 실제 게시 완료를 구분한다.
- 기본 저장소는 기존 .local/mlflow/mlflow.db와 artifacts를 재사용한다. 환경 설정으로 추적 URI를 지정할 수 있으며 인증 정보는 로그·태그·DB 메타데이터에 남기지 않는다.
- MLflow에는 코드 커밋/소스 해시, 모델 이름·revision·설정·시드, 입력/대본/음성/영상 해시, 단계 시간과 최종 상태를 기록한다. 원문 근거·프롬프트·검토·실패 상세를 JSON 아티팩트로 보존한다. 게시 영상과 대표 프레임도 해시를 확인해 연결한다.
- PostgreSQL 기록을 원본으로 유지한다. 같은 시도를 재동기화하면 기존 MLflow run을 재사용한다. 추적 장애를 정상 완료로 위장하지 않고 DB에 PENDING/ERROR 상태로 보존해 재동기화한다. 추적 장애만으로 고비용 미디어 생성을 반복하지 않는다.
- 게시 여부는 기존 DB 트랜잭션으로 확정한다. MLflow에는 생성 완료와 게시 완료를 별도 태그로 표시하며, 최종 DB 저장 이후의 동기화도 재실행할 수 있어야 한다.
- 이미 생성된 개선 샘플과 완료 영상 전체를 소급 연결한다. 과거 버전이 없으면 legacy-unversioned 및 partial lineage로 명시하고, 소급 가져오기와 실제 실행을 구분한다. 기존 영상은 우선 메타데이터를 연결하고 미디어 소급 보관 여부를 별도 표시한다. 없는 과거 정보는 추정해 채우지 않는다. 기존 실험 가져오기 기능은 유지한다.

## 검토한 대안
- 수동 import만 사용: 기본 워커 영상과 run ID가 연결되지 않아 제외한다.
- MLflow 장애 시 생성물을 버리고 재생성: 비싼 GPU 작업과 게시 멱등을 해치므로 제외한다.
- 기존 모든 영상을 새 버전으로 표시: 실제 이력을 훼손하므로 제외한다.

## 결과
2026-11-25 구현하고 PostgreSQL 격리 스키마·실제 MLflow SQLite 테스트를 포함한 129개 테스트를 통과했다. 같은 시도 재실행과 동시 동기화, run 생성 직후 매핑 복구, 게시 통지 유실, 서버 장애 후 임시 파일 삭제·재전송, 같은 바이트의 다중 씬 참조, 해시 변조, 중단 소유권 회수를 검증했다. 기존 수동 MLflow 가져오기 테스트도 활성화해 통과했다.

기존 완료 영상 436건을 소급 연결하고 모든 run ID·게시 태그·버전 및 알려진 코드/영상 해시를 대조했다. 432건의 버전 미상 이력은 legacy-unversioned/partial로 명시했고 4건은 원래 grounded-scenes-v1을 유지했다. 과거의 코드·모델 revision을 추정하지 않았다.

별도 개선 샘플 141의 run 39b741548b154b90a06f42c7e4a45fb0은 UNPUBLISHED이며 미디어 13개를 다시 다운로드해 SHA256을 검증했다. 새 기본 워커가 재사용 없이 1651 기사를 자동 생성·게시했고, 35초 영상과 DB COMPLETED 및 run 988d2cd409ef4e3e983584a79b27fb54의 PUBLISHED/SYNCED/ARCHIVED 연결을 확인했다. 이 건도 미디어 13개의 다운로드 해시가 일치했다. 최종 완료 영상 437건 전부 run ID와 연결됐다.

UI의 HTTP·run API·영상 다운로드를 확인했다. 생성/게시/동기화/아티팩트 보관 상태를 별도로 유지한다. 추적 서버 장애에 대비한 스풀은 .local에 보관하고 성공한 파일만 정리한다. 과거 run 시각을 소급 등록할 때 원본 시각을 태그/기록에 보존하며 UI 음수 시간을 방지한다. 보완 버전으로 연속 워커를 다시 가동했다.

구현과 운영 SQL·명령은 lattae-feed PR #4의 docs/mlflow-lineage.md에 기록했다. MLflow 추적은 사람의 사실/화질 검수나 모델 학습·배포 시스템 전체를 대신하지 않는다.
