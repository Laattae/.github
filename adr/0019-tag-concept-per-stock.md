# 0019. 여러 축에 붙은 같은 값은 지우지 않고, 종목당 한 개념으로 센다

- 상태: 승인
- 날짜: 2026-11-27
- 범위: StocksTag

## 맥락

같은 값이 여러 축에 따로 존재한다. 두 축 이상에 있는 값이 207개였고(product·raw_material 102, application·product 99), 같은 종목에 같은 값이 두 축으로 붙은 경우가 78건이었다(케이티·SK텔레콤·현대건설의 데이터센터 = application + product). 뉴스 매칭 때 축별 점수를 그냥 더하면 이 종목들이 두 번 계산된다.

동의어가 축마다 어긋난 경우도 있었다. `2차전지`는 product에서는 동의어였지만 application에서는 별도 태그로 9종목에 붙어 있었다.

## 결정

- 어긋난 동의어는 축별로 맞춘다. A축의 동의어가 B축에 별도 태그로 있으면 B축에도 같은 동의어를 넣는 후보를 만들고 사람이 승인한다. 축마다 뜻이 다르면 합치지 않는다(product 외환 = 은행 외국환 업무 ≠ exposure 환율).
- 두 축에 붙은 태그는 **지우지 않는다**. 둘 다 근거가 있고, 어느 축인지가 정보이기 때문이다.
- 대신 `stock_tag_concept` 뷰(종목 × 개념 키)로 묶는다. weight는 축 중 최댓값, 어느 축에서 왔는지는 `axes`·`tag_ids`에 남긴다. **뉴스 매칭 점수는 이 뷰 단위로 센다.**
- region은 다른 축과 따로 묶는다. 글자가 같아도 뜻이 다르다(exposure 경기 = 경기 흐름, region 경기 = 경기도).

## 검토한 대안

- **축 우선순위를 정해 한쪽만 남김**: 중복은 없어지지만 "응용처이기도 하고 제품이기도 하다"는 정보가 사라진다.
- **매칭 코드에서 그때그때 중복 제거**: 매칭을 구현하는 사람마다 규칙이 달라진다. 뷰 하나로 고정한다.

## 결과

- 축 간 동의어 어긋남은 16건에서 1건(외환, 일부러 남김)으로 줄었다.
- 같은 종목에 여러 축으로 붙은 값은 80건이 되었다. 대표 표기를 맞추자 같은 값으로 모인 경우가 늘었기 때문이고, 뷰에서 한 번만 센다(태그 연결 9,407 → 개념 9,327, industry_code 제외).
