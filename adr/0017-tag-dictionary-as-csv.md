# 0017. 종목 태그 사전은 CSV가 원본이고, 고칠 때는 후보 → 사람 승인을 거친다

- 상태: 승인
- 날짜: 2026-11-27
- 범위: StocksTag

## 맥락

종목 속성 태그(품목·응용처·고객사·원재료·지역·노출 변수)는 LLM이 사업보고서에서 뽑고, 근거 구절이 원문에 있는 것만 적재한다. 뉴스에 붙이기 전에 표기 중복(Apple/애플), 축 간 어긋남, 상하위 관계, 흔한 태그를 정리해야 했다. 정리를 DB에서 직접 하면 다시 적재할 때 사라지고, 누가 왜 바꿨는지 남지 않는다.

점검하다 두 가지 문제가 나왔다.

1. `tag_synonym`의 키가 `synonym` 하나라서 같은 단어를 축마다 따로 등록할 수 없었다. CSV에는 `에너지저장장치`가 product ESS와 application ESS 둘 다로 있었는데 DB에는 마지막 것만 남았다.
2. 동의어 동기화가 덮어쓰기만 하고 지우지 않아서, CSV에서 빠진 동의어 7행이 DB에 남아 있었다.

## 결정

- 정제 사전은 모두 `data/*.csv`가 원본이고, DB 테이블은 적재 때마다 **지우고 다시 만드는** 사본이다.

  | 사전 | DB | 내용 |
  | --- | --- | --- |
  | `tag_synonyms.csv` | `tag_synonym` | 동의어 → 대표 표기. 키는 `(axis, synonym)` |
  | `tag_stoplist.csv` | (적재 제외) | 근거는 있어도 정보가 없는 값 (0021) |
  | `tag_relations.csv` | `tag_relation` | 상하위·원료 관계 (0020) |
  | `tag_match_exclude.csv` | `tag_match_exclude` | 키워드 매칭에서 뺄 흔한 태그 (0021) |

- 사전을 늘릴 때는 스크립트가 후보 CSV를 만들고, 사람이 `approve`에 1을 적은 행만 `--apply`로 들어간다. 후보를 다시 만들어도 승인 값은 이어받는다. 연쇄 동의어(A→B, B→C)는 반영할 때 최종 대표로 이어 준다.
- 근거 검증은 이 과정에서 끄거나 우회하지 않는다. stoplist는 검증을 통과한 값을 더 거르기만 한다.

## 검토한 대안

- **DB에서 직접 고침**: 빠르지만 다시 적재하면 사라지고 이력이 없다.
- **LLM이 바로 반영**: 동의어 후보는 LLM이 잘 찾지만 뜻이 다른 것을 합치는 경우가 있다(product 외환 = 은행 외국환 업무, exposure 외환 = 환율). 사람 승인을 거친다.

## 결과

- 동의어는 254행에서 419행으로 늘었고 DB와 CSV가 일치한다. 적재를 두 번 돌려 내보낸 결과가 바이트 단위로 같은 것을 확인했다.
- 단계별 수치는 StocksTag `data/refine/step*.txt`, 결정 상세는 `docs/PIPELINE.md` "태그 정제"에 있다. DB 덤프는 Release `v0.3-tags`.
